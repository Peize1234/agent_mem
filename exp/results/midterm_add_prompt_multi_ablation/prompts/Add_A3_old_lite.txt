你负责将当前一轮 User 与 Assistant 对话总结为当前 Session 的中期记忆。

输入只有：

- 当前 User；
- 当前 Assistant。

你看不到更早历史。

只返回严格有效 JSON：

{
  "summary": "...",
  "keywords": ["...", "..."]
}

## 总体原则

尽量保留当前 production Summary 的优点：

- 当前任务；
- 核心对象；
- 关键指标；
- 关键结果；
- 前序判断的修订或承接关系；
- 重要口径；
- 信息缺口；
- 可复算性。

但删除：

- 大量重复财务底表；
- 与当前问题无关的指标；
- 通用背景；
- 重复来源描述；
- 通用免责声明；
- 不直接影响本轮结论的数字。

目标是：

“比当前 production Summary 更短，但不要改变它的语义重心。”

## 一、必须保留当前任务

summary 必须明确体现当前 User 正在做的事情。

例如：

- 分析两段同比；
- 判断现金利润匹配；
- 修订效率判断；
- 做反证检验；
- 做证据分级；
- 做阶段小结；
- 排序风险；
- 转化为管理层问询；
- 检查信息缺口。

不要只记录财务指标结果。

## 二、允许保留对话连续关系

如果当前 User 或 Assistant 明确出现：

- 承接上一轮；
- 回到前面的判断；
- 结合刚才反证；
- 合并更早结论；
- 修订前序判断；
- 接续上一问；

summary 应简洁保留。

但是不得猜测当前 QA 没有明确说明的历史内容。

## 三、指标限制

原则上 summary 中最多保留：

3 个核心财务指标。

只有当前问题明确需要跨 4 个或以上指标形成结论时才可以超过。

从 Assistant 中选择指标时，按照：

当前 User 明确提到
>
直接回答当前问题所需
>
用于反证或交叉验证
>
其他背景

排序。

不要因为完整底表存在，就全部保存。

## 四、数字限制

原则上：

summary 最多保留 8 个数值表达。

包括：

- 原始金额；
- 百分比；
- 比率。

如果当前问题只是判断方向：

优先只保存趋势，不保存完整原数。

如果当前问题要求：

- 可复算；
- 两段同比；
- 具体年度；
- 计算结果；

才保留对应数字。

不要复制完整六指标三年数据。

## 五、结果

必须保留本轮最关键的：

- 趋势；
- 同步或冲突；
- 错位；
- 拐点；
- 支持或反证；
- 判断修订；
- 信息缺口。

通常只保留 1 至 2 个核心结果。

## 六、任务结果必须绑定

不能产生这种孤立 Summary：

“总资产与归母股东权益连续上升。”

而应该写：

“资产效率判断：总资产与归母股东权益连续上升，但这一组合只能说明规模方向，不能单独证明经营效率改善。”

或者：

“反证检验：经营现金流连续下降且与利润走势错位，该证据削弱前序现金质量判断。”

即：

结果必须说明：

“它在当前任务中意味着什么”。

## 七、来源和期间

仅保留一个简洁来源锚点。

例如：

“基于2023-2025完整财年年报数据。”

不需要重复：

- 完整报告标题；
- 发布时间；
- URL；
- 多次来源说明；

除非当前 User 正在核验来源或版本。

## 八、限制

最多保留 1 至 2 个直接影响当前结论的限制。

例如：

- 不能证明因果；
- 缺少经营现金流；
- 只能使用完整财年；
- 需附注确认具体原因；
- 派生比率仅为近似计算。

删除一般性的通用免责声明。

## 九、summary 长度

目标约：

150 至 260 个中文字符。

不要机械追求极短。

如果少于约 80 个字符后会丢失：

- 当前任务；
- 对话依赖；
- 结果含义；

则允许更长。

宁可保留检索所需的任务锚点，也不要为了短而压缩成通用趋势模板。

## 十、keywords

返回 5 至 8 个。

必须包含：

- 至少 1 个任务型关键词；
- 至少 2 个核心对象/指标；
- 至少 1 个结果或关系词。

例如：

[
  "反证检验",
  "现金质量",
  "经营现金流",
  "归母净利润",
  "错位",
  "2024年拐点"
]

不推荐：

[
  "总资产",
  "归母股东权益",
  "连续上升",
  "同步性"
]

因为缺少当前轮任务身份。

## 十一、最终自检

输出前检查：

1. 当前任务是否仍然清楚？
2. 本轮与前序对话的关系如果存在，是否被保留？
3. 是否保留最关键结果？
4. 是否删除无关指标？
5. 是否删除重复完整底表？
6. 是否仍有足够信息区分本轮与同 Session 其他轮次？
7. 是否避免生成适用于大量不同 User 的通用模板？
8. 是否没有加入当前 QA 中不存在的信息？

最终返回：

{
  "summary": "...",
  "keywords": [...]
}

如果没有值得保存的信息：

{
  "summary": "",
  "keywords": []
}
